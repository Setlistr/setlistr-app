# Delegation Audit

Read-only audit of how artist delegation ("acting as") is represented and
enforced across the client, API routes, and database. Repo: `setlistr-2/`,
audited from `main`.

---

## 1. Delegation / artist-context state — client representation

No React Context/Provider/hook exists. The closest equivalent is
`app/app/dashboard/page.tsx` — it owns the `actingAs` state, the artist-switcher
UI, and is the only place that *writes* the persisted value. Every other page
independently re-reads the same `localStorage` key directly; there is no shared
module.

**Path:** `app/app/dashboard/page.tsx` (874 lines)

Load-bearing pieces:

```ts
const ACTING_AS_KEY = 'setlistr_acting_as'
...
type ManagedArtist = { artist_id: string; artist_name: string; role: string; avatar_url?: string | null }
type ActingAs      = { artist_id: string; artist_name: string } | null
...
  const [managedArtists, setManagedArtists]     = useState<ManagedArtist[]>([])
  const [actingAs, setActingAs]                 = useState<ActingAs>(null)
```

Read side (on mount):
```ts
        const savedActingAs = localStorage.getItem(ACTING_AS_KEY)

          try {
            const parsed = JSON.parse(savedActingAs)

```

Write side:
```ts

    setSwitcherOpen(false); setLoading(true)
    setLookupName(null); setUpcomingShows([]); setTodayShow(null)

  async function switchToOwn() {
    setSwitcherOpen(false); setLoading(true)
    setActingAs(null); localStorage.removeItem(ACTING_AS_KEY)

  }
```

Every other consuming page (`app/app/show/new/page.tsx`, `app/app/new/page.tsx`,
`app/app/stats/page.tsx`, `app/app/career-map/page.tsx`) does its own independent
`localStorage.getItem('setlistr_acting_as')` + `JSON.parse(...)` — there is no
`useActingAs()` hook or shared reader.

## 2. Delegation relationship in the database

No SQL schema for this table exists anywhere in the repo. `supabase-schema.sql`,
`supabase/migrations/*.sql`, and `lib/reconciliation/*.sql` contain zero
`CREATE TABLE artist_delegates`, and there's no `ArtistDelegate` type in
`types/index.ts`. The columns below are entirely reconstructed from the
`.select()`/`.insert()`/`.update()` calls across the 8 API routes that touch it.

**Table:** `artist_delegates`

| Column | Evidence |
|---|---|
| `id` | `app/api/team/delegates/route.ts:22` `.select('id, delegate_id, role, accepted_at, invited_at, invite_token')` |
| `artist_id` | `app/api/team/invite/route.ts:130` `artist_id, delegate_id: delegateUser.id, role, invited_by: artist_id,` |
| `delegate_id` | same insert, and `.eq('delegate_id', user.id)` in `app/api/team/managed-artists/route.ts:20` |
| `role` | `app/api/admin/assign-delegate/route.ts:19` `const { artist_id, delegate_id, role = 'manager' } = await req.json()` |
| `invited_by` | `app/api/team/invite/route.ts:130,132` — `invited_by: artist_id` |
| `invite_token` | `app/api/team/accept/route.ts:24` `.eq('invite_token', token)` (auto-generated by the DB — never set on insert in any route) |
| `invited_at` | `app/api/team/delegates/route.ts:23` select list |
| `accepted_at` | `app/api/team/accept/route.ts:80` `.update({ accepted_at: new Date().toISOString() })` |

Full insert shape (`app/api/team/invite/route.ts:127-135`):
```ts
    const { data: delegate, error } = await supabase
      .from('artist_delegates')
      .insert(delegateUser ? {
        artist_id, delegate_id: delegateUser.id, role, invited_by: artist_id,
      } : {
        artist_id, delegate_id: artist_id, role, invited_by: artist_id,
      })
      .select('id, invite_token')
      .single()
```

Superadmin pre-accepted insert (`app/api/admin/assign-delegate/route.ts:46-54`):
```ts

      .from('artist_delegates')
      .insert({
        artist_id,
```

No FK constraints, defaults, or `NOT NULL` markers are visible anywhere in the
repo for this table.

## 5. RLS policies for `artist_delegates`, `performances`, `performance_songs`

Searched every `.sql` file in the repo (`supabase-schema.sql`,
`supabase/migrations/*.sql`, `lib/reconciliation/*.sql`).

**`performances`** — exactly one policy:
```sql
ALTER TABLE performances ENABLE ROW LEVEL SECURITY;
...
CREATE POLICY "performances_own" ON performances FOR ALL USING (auth.uid() = user_id);
```

**`performance_songs`** — exactly one policy:
```sql
ALTER TABLE performance_songs ENABLE ROW LEVEL SECURITY;
...
CREATE POLICY "songs_own" ON performance_songs FOR ALL
  USING (EXISTS (SELECT 1 FROM performances WHERE id = performance_id AND user_id = auth.uid()));
```

**`artist_delegates`** — **no policy exists.** There is no `CREATE TABLE
artist_delegates`, no `ALTER TABLE artist_delegates ENABLE ROW LEVEL SECURITY`,
and no `CREATE POLICY` referencing it anywhere in the repo's SQL files. Stating
this explicitly per the task: the table's RLS status (if any exists in the live
database) is not visible in this codebase at all.

Neither `performances_own` nor `songs_own` references `artist_delegates` or any
delegation concept — both are strict `auth.uid() = <owner>` checks. This is
consistent with the pattern in section 3/6: because RLS has no concept of
delegation, every delegated read is routed through service-role API endpoints
that bypass RLS and enforce the delegation check in application code instead.

## 6. Per-route delegation verification (8 routes touching `artist_delegates`)

| Route | Verifies accepted delegation before acting? |
|---|---|
| `app/api/song-debuts/route.ts` | **Yes** |
| `app/api/admin/assign-delegate/route.ts` | **No — by design** (admin-gated, not delegation-gated; this route *creates* delegations) |
| `app/api/team/accept/route.ts` (GET) | **No delegation check** (returns limited invite metadata + a computed `is_intended_recipient` flag) |
| `app/api/team/accept/route.ts` (POST) | **N/A — verifies caller identity instead** (accepting *is* what creates the delegation, so "already accepted" can't be the gate) |
| `app/api/team/invite/route.ts` | **No — no auth check of any kind** |
| `app/api/team/managed-artists/route.ts` | **Yes** (self-scoped by construction) |
| `app/api/team/delegates/route.ts` (GET/DELETE) | **Yes — but verifies artist identity, not delegate-of relationship** |
| `app/api/team/context-data/route.ts` | **Yes** |
| `app/api/account/delete/route.ts` | **N/A — self-scoped cleanup**, operates only on `invited_by = <caller's own id>` |
