# Setlist intake: five questions

**What this is for:** a separate track from the prototype test. Record the answers here, not in the adoption findings. They inform how a confirmed setlist could reach Setlistr with little effort. They don't show adoption.

**When to ask:** at the end of the session, after section 6 of `feedback-template.md`, of the same artist and the person who handles their setlists. Ask each person, and note who answered. Record exact words where possible; if they show you something (a file, a message, a photo), note what you saw.

| # | Question | Answer: artist | Answer: setlist handler | Seen, not just said? |
|---|---|---|---|---|
| 1 | **Who writes the final setlist for a show, and when?** (Not the plan: the one taped to the stage.) | | | |
| 2 | **What form is it in?** Paper, a phone note, a spreadsheet, a PDF, a message? Can you show me the last one? | | | |
| 3 | **Where does it already go after it's written?** Who gets a copy (crew, FOH, band chat, email, a shared folder), and where is it kept afterwards? | | | |
| 4 | **Does that copy get updated with what was actually played?** Skips, swaps, an extra encore: who records those, and how often does it happen? | | | |
| 5 | **When something on it is unclear, who could answer quickly without being chased?** How would you want to be asked: a message, in the app, or not at all? | | | |

**After the session:** add the date, the names by role, and anything they offered to send. Don't suggest a route during the session.
